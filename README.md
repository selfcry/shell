# ClubShell — оболочка для компьютерного клуба «Мираж PRO»

Каркас: окно блокировки с вашим дизайном, служба-страж и заглушка сервера.

## Как это устроено

```
┌────────────────────────── Windows ──────────────────────────┐
│ ClubShell.Service  (SYSTEM, автозапуск, перезапуск при сбое) │
│   ├─ GuardianWorker : раз в 2 с проверяет окно в сессии      │
│   │    гостя и запускает заново (CreateProcessAsUser)        │
│   ├─ HeartbeatWorker: пульс серверу раз в 5 с; тишина дольше │
│   │    OfflineGraceSec (30 с) = связь потеряна               │
│   └─ ControlPipeServer ◄── named pipe «ClubShell.Control» ─┐ │
│        хранит конфиг и хеш PIN, проверяет PIN сам           │ │
│                                                            │ │
│ ClubShell.Locker   (сессия гостя, WinForms + WebView2)     │ │
│   ├─ ServiceLink (клиент pipe, сам переподключается) ──────┘ │
│   ├─ режим locked : весь экран, topmost, хук клавиатуры      │
│   ├─ режим session: панель 380×100 в углу, клавиши свободны  │
│   ├─ SessionManager (таймер, баланс)  ◄─ ClubShell.Core      │
│   └─ IClubApi ──► FakeClubApi (заглушка)  → потом сервер     │
│                                                              │
│ ui/ (TypeScript + Vite) — заставка → вход → тариф → панель   │
│   общается с Locker JSON-сообщениями (ui/src/protocol.ts)    │
└──────────────────────────────────────────────────────────────┘
```

Поток: ПК включился → заставка (ролик по кругу, `ui/public/media/intro.mp4`) → **пробел** →
форма входа → выбор тарифа (1 / 3 / 5 часов / ночь, как на mirage-ptg.ru/prices) →
панель с таймером → по окончании снова блокировка.

## Разработка интерфейса (на любой ОС)

```bash
cd ui && npm install && npm run dev      # откроется с макетом хоста: логин demo / demo, админ-PIN 0000
```

Свои файлы кладите в `ui/public/media/`: `logo.webp` (логотип клуба) и `intro.mp4` (ролик).
Если файлов нет, интерфейс показывает анимированный фон и надпись «МИРАЖ PRO».

## Сборка и установка на Windows 11 (PowerShell от администратора)

1. Установите .NET 8 SDK, Node.js и среду выполнения WebView2 (есть в Windows 11).
2. `.\scripts\build.ps1` — собирает интерфейс и обе программы в `dist\`.
3. `.\scripts\install.ps1` — ставит службу, права на папку, автоперезапуск.
4. Создайте обычного (не админского) пользователя `guest` с автовходом и один раз войдите им.
5. `.\scripts\harden.ps1 -GuestUser guest` — запрет диспетчера задач, Win+R, regedit, подмена оболочки.
   Снять: добавить `-Undo`. **Сначала проверьте всё в виртуальной машине.**

Тестовые гости заглушки: `demo / demo` (600 ₽), `vip / vip` (2000 ₽).
PIN администратора создаётся при первом запуске службы: открытый — в `C:\ProgramData\ClubShell\admin-pin.txt`
(прочитайте и удалите), в `config.json` хранится только хеш. Папка `ClubShell` закрыта для всех, кроме SYSTEM и администраторов.
Выход для обслуживания: на заставке **Ctrl+Shift+F12** → PIN. Окно отправляет PIN службе, служба проверяет его
(5 ошибок — минута без попыток) и создаёт файл `maintenance`; пока файл есть, окно не перезапускается.

## Связь службы и окна (named pipe)

Токен ПК (`PcToken`) есть только у службы (SYSTEM, `C:\ProgramData\ClubShell\config.json` закрыт для гостя).
Окно блокировки работает под гостем, поэтому токена не получает: все запросы к серверу клуба оно передаёт службе,
служба вызывает сервер и возвращает результат.

| Направление | Сообщение | Зачем |
|---|---|---|
| служба → окно | `hello {pcName, zone, requireService, serverUrl}` | имя ПК, зона; адрес сервера — только для обложек и пинга (не секрет) |
| служба → окно | `state {offline, reason}` | каждые 2 с; `offline=true` → окно закрывает сессию и блокируется |
| служба → окно | `command {name, …}` | команды сервера: `endSession`, `lock`, `message`, `sync`, `balance` |
| окно → служба | `status {locked, sessionActive}` | каждые 2 с и сразу при подключении; служба по нему проверяет, что окно живо и заблокировано |
| окно → служба | `adminPin {pin}` → `adminResult {ok}` | выход для обслуживания |
| окно → служба | `request {id, op, …}` → `response {id, ok, error, fail, …}` | `op`: `login`, `register`, `logout`, `start`, `stop`, `catalog`, `speedtest`; `fail=true` — нет связи с сервером |

Гостя, от имени которого начинается и завершается сеанс, служба берёт из своего состояния (кто вошёл через неё
по ответу сервера), а не из сообщения окна. Тестовый запуск без службы (`scripts/test-all.ps1`, `CLUBSHELL_TEST=1`
+ `CLUBSHELL_SERVER_URL`/`CLUBSHELL_PC_TOKEN`) по-прежнему ходит на сервер прямо из окна; на ПК с установленной
службой эти переменные игнорируются (`DevFlags`).

Блокировка при потере связи работает в обе стороны:
- **сервер молчит** (пульс не проходит 30 с) → служба шлёт `offline` → окно завершает сессию и показывает «Нет связи с сервером», вход закрыт;
- **служба молчит** (убита или остановлена) 15 с → окно блокируется само («Служба не отвечает»). Для разработки без службы задайте `CLUBSHELL_DEV_URL`: проверка отключается.
- Завершение сессии не зависит от сервера: окно сначала блокируется, потом отправляет отчёт `stop`; если он не ушёл, ПК всё равно заблокирован.

Проверить без настоящего сервера: создайте пустой файл `C:\ProgramData\ClubShell\simulate-offline`
(заглушка начнёт «терять связь»), через 30 с активная сессия закроется; удалите файл — связь вернётся.

## Что уже защищено

- Хук клавиатуры гасит Win, Alt+Tab, Alt+Esc, Ctrl+Esc, Alt+F4; закрыть окно нельзя.
- Окно каждые 0,5 с возвращает себе фокус и topmost.
- WebView2: без меню, DevTools, F5/F12 и новых окон.
- PIN: 5 ошибок → блокировка попыток на минуту; сравнение за постоянное время.
- Служба под SYSTEM, перезапуск при сбое, файлы программы без права записи для гостя.
- **Токен ПК не попадает к гостю**: его нет ни в `hello`, ни в памяти окна; вход, старт/стоп сеанса, каталог и тест скорости делает служба.
  Сервер вдобавок требует, чтобы гость вошёл с паролем на этом ПК, прежде чем с его баланса купят время.
- **Канал (pipe)**:
  - служба создаёт первый экземпляр с `FirstPipeInstance` до чистки профиля и стража (порядок в `Service/Program.cs`), не больше 4 экземпляров;
  - строка не длиннее 64 КБ от окна (4 МБ от службы — каталог) — иначе канал рвётся, без чтения «бесконечной» строки в память;
  - не больше 4 одновременных запросов от клиента;
  - служба принимает `status`, `adminPin` и `request` только от процесса окна, запущенного стражем (PID клиента канала = PID, который вернул `CreateProcessAsUser`); другие процессы гостя могут подключиться, но их сообщения игнорируются;
  - окно проверяет сервер канала (`GetNamedPipeServerProcessId`): процесс должен работать в сессии 0 (туда гость запустить ничего не может) и, если путь читается, быть `ClubShell.Service.exe` рядом с папкой окна. Проверить, что это именно LocalSystem, из-под гостя нельзя (токен SYSTEM-процесса ему не открыть), опора — сессия 0 и путь.
- **Страж следит за своим процессом**, а не за именем: хранит handle процесса, который запустил. Процесс гостя с именем `ClubShell.Locker` в сессии гостя закрывается. После перезапуска службы уже работающее окно берётся под надзор, только если это наш файл.
- **Мьютекс окна** `Global\ClubShell.Locker` создаёт служба при старте с DACL (гостю — только ожидание/освобождение). Обычный пользователь не может создавать объекты в `Global\`, так что занять имя заранее или закрыть к нему доступ гость не может. Без службы (тест) окно берёт `Local\ClubShell.Locker`.
- **Контроль сеанса службой** (`SessionEnforcer`): если по пульсу сервера на ПК нет оплаченного сеанса (или связь потеряна), а окно, запущенное стражем,
  `EnforceLockSec` (по умолчанию 15 с, `0` — выключено, в `config.json`) не подтверждает `status {locked:true}` — служба завершает сеанс Windows гостя
  (`WTSLogoffSession`) и перезагружает ПК. Так закрывается обход «приостановить / подменить / заморозить окно». Первые 60 с после входа в Windows
  и режим обслуживания по PIN не проверяются.
- **Конец сеанса**: окно сначала блокируется (`SetMode(locked)`), затем закрывает все процессы гостя в его сессии, кроме оболочки и системных
  (`GuestProcesses`), затем отправляет отчёт серверу и перезагружает ПК (ждёт отчёт до 5 с). В тестовом режиме процессы не закрываются.

### Проверить на виртуальной машине Windows (на macOS только собирается)

1. Служба стартует, в журнале нет `Pipe … is already taken`; окно подключается к каналу (в `%LocalAppData%\ClubShell\locker.log` нет `Pipe server rejected`) — то есть проверка сессии 0 и пути службы проходит на реальной Windows.
2. Вход, регистрация, старт и стоп сеанса, каталог с обложками и тест скорости работают через службу; в `hello` (например, `PipeList`/свой клиент) нет токена.
3. Свой клиент канала из-под гостя: подключается, но `status`/`request`/`adminPin` игнорируются (в журнале службы `is not the locker started by the guardian`).
4. Канал-подделка: процесс гостя, создавший `\\.\pipe\ClubShell.Control` до службы (например, при остановленной службе), окном отвергается.
5. Без сеанса: приостановить окно (Process Explorer → Suspend) — через ~15 с сеанс Windows гостя завершается, ПК перезагружается. Во время оплаченного сеанса приостановка не приводит к выходу.
6. Сеанс кончился на сервере (админ «Завершить» / истекло время), а окно убито и заменено процессом `ClubShell.Locker.exe` из папки гостя — страж его закрывает, запускает своё окно; если окно не подтверждает блокировку, служба делает выход и перезагрузку.
7. Мьютекс: из-под гостя не создать `Global\ClubShell.Locker`; окно при живой службе открывает его, второй экземпляр окна закрывается.
8. Конец сеанса закрывает игры/браузер гостя, но не трогает `explorer`, WebView2 оболочки и системные процессы; отчёт `stop` доходит до сервера до перезагрузки.
9. Перезапуск службы (`Restart-Service ClubShellService`) во время сеанса: окно не закрывается (страж берёт его под надзор), сеанс не прерывается.
10. Нет ложных выходов: медленная загрузка Windows (первые 60 с), обслуживание по PIN, обрыв связи с сервером при работающем окне (окно блокируется само и подтверждает это).

## Что не сделано (следующие шаги)

1. **Настоящий сервер** вместо `FakeClubApi` (интерфейс `IClubApi` уже готов): гости, тарифы, брони, оплата, WebSocket-события.
2. **Пока офлайн-блокировка завязана на пульс заглушки.** С настоящим сервером нужно решить, что делать при обрыве: сразу блокировать или давать доиграть оплаченное время.
3. **Действие после сессии:** сброс профиля гостя или выход из Windows; сохранение игровых профилей на NAS.
4. **Ночной тариф** в заглушке зависит от часов ПК; на сервере время должно быть серверным.
5. Ctrl+Alt+Del хуком не ловится: закрывается политиками из `harden.ps1`.
6. Не проверено на живой Windows: код собирается (`dotnet build` без ошибок), UI проверен в браузере с макетом, формат сообщений pipe,
   хеш PIN и завершение сессии без сервера проверены тестом. Сам pipe с ACL, служба и запуск в сессии гостя ждут проверки в виртуальной машине.
7. Окно работает под гостем: внедрение кода в сам процесс окна (тот же пользователь) защитой канала не закрывается.
   Нужны средства ОС — обязательный профиль, AppLocker/WDAC (запрет запуска из папок гостя), отключённые отладчики.

## Рабочий стол гостя (режим `session`)

После оплаты тарифа окно блокировки не сворачивается в панель, а становится **рабочим столом**: на весь экран, но не поверх остальных окон
(игры открываются над ним). Хук клавиатуры в этом режиме выключен.

- Вкладки **Игры / Приложения**, поиск, фильтры-чипсы (группы и «С клубными аккаунтами»), сетка обложек 2:3, значки `18+` и «Клубный аккаунт».
- Сверху справа карточка гостя: имя, баланс, время до конца сеанса, кнопка завершения (нужно нажать дважды).
- Внизу — отдельная **панель задач** (см. ниже).
- **Каталог** — файл `ui/config/catalog.json` (id, название, вид, группа, обложка, пути запуска, аргументы). Хост читает его сам:
  показывает только записи, у которых найден хотя бы один путь на этом ПК (URI вроде `steam://` считаются доступными);
  интерфейсу пути не отдаются, запуск идёт **строго по id** из каталога и только пока сессия активна.
- Обложки кладутся в `ui/public/covers/` (2:3, лучше 600×900, до 250 КБ), путь указывается в поле `cover`. Нет файла — рисуется заглушка с инициалами в цветах клуба.
- **Клубные аккаунты через RentalGames** (оплачено, выдачу делает он): записи с `clubAccount` запускают `RentalGames.exe -idgame <код игры> -autostart -user {user}`. В `args` подставляются `{user}` (имя гостя — по нему RentalGames хранит его сохранения) и `{pc}`; значения очищаются от кавычек и управляющих символов и ставятся в кавычки. Коды игр — в списке RentalGames, параметры запуска — в их инструкции. Путь к `RentalGames.exe` искать не нужно: запись `"find:RentalGames.exe"` в `paths` ищет программу сама (реестр установленных программ и App Paths, затем типичные папки и корни всех дисков, результат кэшируется до перезагрузки каталога). Так можно задавать любые программы.
- Рецепты путей для Steam, Epic, Riot, Discord, Microsoft Store — в `docs/smartshell-notes.md`.

### Панель задач (`TaskbarForm`, страница `ui/taskbar.html`)

Отдельное окно у нижнего края экрана, зарегистрированное как **AppBar** (`SHAppBarMessage`): система резервирует под него полосу,
развёрнутые окна его не перекрывают, рабочий стол клуба сжимается на высоту панели. Окно не берёт фокус (`WS_EX_NOACTIVATE`) и не попадает в Alt+Tab.

- Слева кнопка «Рабочий стол» (сворачивает окна и выводит рабочий стол клуба) и **список открытых окон**: значок, заголовок; клик — открыть/развернуть,
  клик по активному — свернуть, `×` или средняя кнопка — закрыть (`WM_CLOSE`). Список строится `EnumWindows` (видимые, без owner, не tool-окна,
  не cloaked), опрос раз в 0,7 с, в интерфейс уходят только изменения. Окна самой оболочки в списке не показываются.
- Справа язык, **громкость/mute** (Core Audio), **сеть**, часы.
- **Полноэкранная игра:** по уведомлению `ABN_FULLSCREENAPP` панель уходит на `HWND_BOTTOM`, после выхода возвращается `HWND_TOPMOST`.
- В режиме `locked` панель скрыта и снимает резерв (`ABM_REMOVE`), в `session` показывается.
- Идентификатор окна из интерфейса проверяется по последнему списку хоста: управлять произвольным `hwnd` нельзя.


### Конец сеанса, очистка и диспетчер задач

- **Завершение сеанса.** Кнопка питания на рабочем столе открывает подтверждение («Компьютер перезагрузится, всё скачанное будет удалено»). После согласия (или когда время вышло, или пропала связь) ПК блокируется и перезагружается (`shutdown /r`).
- **Очистка «как в Langame».** При загрузке Windows служба (`CleanupWorker`, до входа гостя и до старта стража) удаляет содержимое профиля гостя: Загрузки, Документы, Рабочий стол, Изображения, Видео, Музыка, Temp, данные браузеров, Discord, Telegram. Настройки в `config.json`: `GuestUser` (по умолчанию `guest`), `WipeOnBoot`, `WipeDirs`. Защита: чистится только `C:\Users\<GuestUser>` и только перечисленные подпапки внутри; `Administrator`, `Default`, `Public` и т.п. запрещены; ссылки (junction/symlink) не открываются. Установленные игры и Steam не трогаются: чтобы чистить и их, добавьте нужные папки в `WipeDirs` (внутри профиля).
- **Тестовый режим** (`CLUBSHELL_TEST=1`, скрипт `run-test.cmd`): без службы, без хука клавиатуры, выход по PIN 0000; перезагрузка и очистка **не выполняются**, только имитация.
- **Панель задач:** пинг до узла (`CLUBSHELL_PING_HOST`, по умолчанию 1.1.1.1; потом будет адрес клубного сервера), кнопка «Тест скорости» (скачивание и отдача через speed.cloudflare.com, до ~8 с на направление), кнопка «Диспетчер».
- **Диспетчер задач** (`TaskManagerForm`, `ui/taskmgr.html`; Ctrl+Shift+Esc или кнопка на панели): приложения и фоновые процессы гостя, ЦП и память, «Снять» (с подтверждением). Системные процессы и сама оболочка в списке не показываются и не завершаются; завершить можно только процесс из последнего списка. Стандартный диспетчер Windows отключён политикой `DisableTaskMgr` (harden.ps1).
- Запуск ускорен: окна панели и диспетчера загружаются заранее, поиск программ для каталога идёт в фоне.

Проверка без Windows: `cd ui && npm run dev` → `http://localhost:5173/taskbar.html` (макет с тремя окнами). Без проверки на Windows: AppBar, полноэкранный режим, значки.

Проверка без Windows: `cd ui && npm run dev` (макет хоста читает тот же `catalog.json`; `dota2` в макете «не найдена» — для проверки ошибки).
Каталог тестируется отдельно (чтение, отбор по найденным путям, переменные среды).

Ещё не сделано для рабочего стола: ограничение по возрасту (нужна дата рождения с сервера), выдача клубных аккаунтов,
замена `explorer.exe` как оболочки, трей (мышь, язык), каталог с сервера вместо файла.


## Сервер клуба (`src/ClubShell.Server`)

ASP.NET (minimal API) + SQLite. Сервер — единственный источник правды о деньгах и времени: баланс, тарифы, сеансы, ПК.

**Запуск для проверки:** `Club__DataDir=./data ASPNETCORE_URLS=http://127.0.0.1:5080 dotnet run --project src/ClubShell.Server`. При первом запуске создаются база `club.db`, тарифы ARENA (1/3/5 часов, ночь), тестовые гости `demo`/`demo` и `vip`/`vipvip` (отключить: `Club__SeedDemo=false`) и **ключ администратора** `data/admin-key.txt`.

**API для ПК** (заголовок `X-Pc-Token`): `POST /api/pc/login`, `/api/pc/session/start`, `/api/pc/session/stop`, `/api/pc/heartbeat`; `GET /ws/pc` (WebSocket: сервер шлёт команды `endSession`, `lock`, `message`, `sync`, `reboot`, `shutdown`).

**API для админки** (заголовок `X-Admin-Key`): `/api/admin/stats`, `pcs` (список, добавление, удаление, `POST pcs/{id}/command`), `guests` (создать, изменить, пополнить `POST guests/{id}/topup`, история), `tariffs`, `sessions` (список, `POST sessions/{id}/stop`, `add-time`).

**Подключение ПК:** админ добавляет ПК (`POST /api/admin/pcs {"name":"PC-01"}`), получает токен (показывается один раз, в базе только хеш) и вписывает в `C:\ProgramData\ClubShell\config.json` на этом ПК: `"ServerUrl": "https://club.example.ru"`, `"PcToken": "…"`. Без этих полей оболочка работает с тестовой заглушкой.

**Правила:** на ПК и на гостя не больше одного активного сеанса; ночной тариф только 22:00–08:00 по `Club:TimeZone` (по умолчанию Europe/Moscow); списание атомарное; баланс не уходит в минус; пароли гостей PBKDF2; 5 неверных паролей — минута паузы; время вышло — сервер сам закрывает сеанс и командой по WebSocket просит ПК завершиться.

### Нагрузка и оптимизация

Клиенты шлют пульс раз в 5 секунд, поэтому горячие запросы **не трогают базу**:
- пульсы ПК, токены, тарифы и активные сеансы живут в памяти; в SQLite пульсы пишутся пакетом раз в 30 с одной транзакцией;
- проверка окончания сеансов идёт по памяти (раз в 2 с), в базу пишется только факт завершения;
- запись в базу строго по очереди (одна блокировка), SQLite в режиме WAL (`synchronous=NORMAL`, кэш 32 МБ, mmap), индексы под выборки по гостям, платежам и активным сеансам;
- проверка пароля (PBKDF2) — не больше 4 одновременно, чтобы всплеск входов не загрузил процессор;
- сводка админки кэшируется на 3 секунды; ответы сжимаются; ночью (04:00) делается копия базы `VACUUM INTO`, хранится 7 последних.

Проверка на ноутбуке: 100 «ПК» с пульсом в 20 раз чаще реального (≈1570 запросов/с) дали p95 = 21 мс, 0 ошибок, а размер WAL-файла почти не вырос (в базу пульсы не пишутся). Реальная нагрузка 100 ПК — около 20 запросов/с.

### VPS (play2go.cloud)

Для одного клуба (до ~100 ПК) хватает **DE-2: 2 vCPU Ryzen 9 5950X, 4 ГБ RAM, 120 ГБ NVMe, 5,6 €/мес** (DE-1 за 3,4 € годится для небольшого зала, DE-3 за 8,5 € — запас на несколько клубов). Сервер использует ≈200 МБ памяти. Расположение лучше Финляндия или Германия (задержка до Пятигорска ~50–80 мс: для управления клубом это незаметно, а ПК переживают обрыв связи 30 секунд). Учтите: персональные данные граждан РФ по закону (152‑ФЗ) должны храниться в России; для хранения только логинов и балансов клуба проконсультируйтесь или выберите российский хостинг.

Развёртывание: `deploy/install-server.sh` (systemd, пользователь `clubshell`, данные в `/var/lib/clubshell`), HTTPS через Caddy (`deploy/Caddyfile`). Сборка: `dotnet publish src/ClubShell.Server -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true -o publish`.

### Регистрация гостей

Гость регистрируется сам за клубным ПК: «Нет аккаунта? Зарегистрироваться» (логин, пароль, повтор, дата рождения, согласие с правилами). Подтверждения по телефону и SMS **нет**: после регистрации гость сразу попадает к выбору тарифа с балансом 0 ₽, пополняет баланс администратор («Пополнить» у гостя в админ-панели).

Правила сервера: логин 3–24 символа (буквы, цифры, точка, дефис, подчёркивание), пароль 6–64 символа и не равен логину, дата рождения обязательна (нужна для возрастных ограничений игр), логин уникален; не больше 10 регистраций в час с одного ПК и 120 в час по клубу. Админ может создать гостя и вручную («Новый гость»), заблокировать его или сменить пароль.

## Релизы и проверка

Каждая программа собирается своим workflow (`.github/workflows/build-*.yml`: Locker, Service, Admin, Server для Linux и Windows). После успешной сборки на main архив `ClubShell.<Программа>-<платформа>.zip` выкладывается в [GitHub Releases](https://github.com/selfcry/shell/releases): скользящий релиз `latest` обновляется при каждой сборке, а тег `v1.2.3` (`git tag v1.2.3 && git push --tags`) создаёт постоянный релиз. Проверка «всё вместе» на виртуалке: `scripts/test-all.ps1` и [docs/test-on-windows.md](docs/test-on-windows.md); тот же скрипт (режим `-ServerOnly`) гоняется в CI на Windows (`e2e-server-windows.yml`).

### Развёрнуто на VDS (cryvx.ru)

Сервер клуба работает на VDS (`ssh vds`, Ubuntu, play2go) по адресу **https://cryvx.ru**.
- Программа: `/opt/clubshell-server` (самодостаточная, .NET ставить не нужно), служба `clubshell-server` (systemd), данные и копии базы в `/var/lib/clubshell`, слушает только `127.0.0.1:5080`. Демо-гостей нет (`Club__SeedDemo=false`), в журнал идут только предупреждения.
- HTTPS: на этом же VDS уже есть nginx с SNI-роутером на 443 (`/etc/nginx/stream.d/sni-router.conf`). Для cryvx.ru добавлена строка в карту роутера и сайт `/etc/nginx/sites-available/cryvx.ru` (копия: `deploy/nginx-cryvx.ru.conf`); сертификат Let's Encrypt выпускается и продлевается certbot-ом (webroot `/var/www/cryvx-acme`). Остальные сайты на сервере не менялись, копия настроек nginx до изменений: `/root/backup`.
- **Ключ администратора:** `ssh vds cat /var/lib/clubshell/admin-key.txt`. Приложение администратора (`ClubShell.Admin.exe`) по умолчанию подключается к `https://cryvx.ru`, нужен только ключ.
- **Веб-админка:** **https://cryvx.ru/admin/** — та же панель в любом браузере, с настоящими данными. Ключ запоминается в браузере; на чужом компьютере нажмите «Выйти». Страница отдаётся nginx из `/var/www/clubshell-admin` со строгим CSP и запретом встраивания во фрейм.
- **Подключение ПК клуба:** админ-панель → «Компьютеры» → «Добавить ПК» показывает готовую команду: на ПК в папке с программой от администратора `.\scripts\install.ps1 -PcToken '…' -PcName 'PC-05'` — служба ставится и сразу подключается к серверу (адрес по умолчанию `https://cryvx.ru`). Потерянный токен: карточка ПК → «Новый токен» (старый сразу перестаёт работать).
- **Обновление сервера и веб-админки одной командой:** `deploy/deploy-vds.sh` (собирает локально, копия базы перед заменой, проверка `/health`, при неудаче автоматический откат). Только веб-админка: `deploy/deploy-vds.sh --admin`; вернуть прошлую версию: `deploy/deploy-vds.sh --rollback`. Конфиг nginx (`deploy/nginx-cryvx.ru.conf`) выкладывается отдельно: `scp` в `/etc/nginx/sites-available/cryvx.ru`, затем `nginx -t && systemctl reload nginx`.
- **Резервные копии:** каждую ночь в 04:00 по времени клуба (`VACUUM INTO` + проверка `PRAGMA integrity_check`), хранятся 14 последних в `/var/lib/clubshell/backups`, плюс копия перед каждым деплоем (5 последних). **Восстановление:** `systemctl stop clubshell-server; cd /var/lib/clubshell; cp backups/club-ГГГГММДД.db club.db; rm -f club.db-wal club.db-shm; chown clubshell: club.db; chmod 600 club.db; systemctl start clubshell-server`. Копии лежат на том же диске — для защиты от потери VDS их нужно дополнительно забирать к себе (`scp vds:/var/lib/clubshell/backups/* .`).
- **Защита сервера:** systemd-песочница (`systemd-analyze security clubshell-server` — 1.6 «OK»), данные и ключ доступны только пользователю `clubshell` (0700/0600), nginx ограничивает частоту запросов (админ-API, вход/регистрация, остальное API), HSTS, токен ПК принимается только в заголовке. Покупка сеанса возможна только для гостя, который вошёл на этом ПК по паролю; повтор пополнения с тем же `requestId` не проводится; все изменения из админки пишутся в «Журнал».

## Работа клуба: смены, бар, брони, бонусы, сотрудники

- **Смена и касса.** Кассир открывает смену (сумма в кассе на начало), при пополнении выбирает способ оплаты (наличные, карта, СБП). Отчёт смены: пополнения по способам, списания, продажи бара, выручка за сеансы, оплачено бонусами, новые гости; при закрытии вводится посчитанная сумма, показывается расхождение. Отчёт уходит в Telegram.
- **Зал.** Компьютеры по зонам с живыми таймерами: свободен, сеанс, меньше 10 минут, скоро бронь, гость зовёт администратора, нет связи.
- **Вызов администратора.** Кнопка на панели задач и на главном экране; в админке звук и плашка «Иду» на любой вкладке, в Telegram — сообщение.
- **Во время игры.** На панели задач остаток времени и баланс; за 10, 5 и 1 минуту и при сообщении администратора поверх игры всплывает окно (не забирает фокус).
- **Брони.** На логин гостя, на ПК и время. За 15 минут до начала ПК держится за гостем (другие не войдут), бронь снимается через 30 минут опоздания; сеанс, заходящий на чужую бронь, купить нельзя.
- **Бонусы и уровни.** Отдельный бонусный баланс: при покупке времени сначала тратятся бонусы (1 бонус = 1 ₽). Кешбэк бонусами по уровню гостя (уровень — по сумме, потраченной на время: Новичок 0%, Бронза 3%, Серебро 5%, Золото 7%, Платина 10%; лестница меняется в админке). Промокоды на бонусы (лимит использований, срок, один раз на гостя) — гость вводит на главном экране.
- **Тарифы по времени суток.** У тарифа можно задать окно «с … до …» (например, «Утро» 08–14); купить можно только в окне, сеанс заканчивается в конце окна. Ночной тариф — то же окно 22–08.
- **Бар и склад.** Товары с остатками и категориями, продажа на стойке (наличные, карта, СБП, с баланса гостя), приход и списание. Гость заказывает с ПК (кнопка-чашка на главном экране) с оплатой с баланса — заказ всплывает у администратора; «Выдан» или «Отменить» (товар на склад, деньги на баланс).
- **Аналитика.** Выручка по дням, начало сеансов по часам, популярность тарифов, загрузка ПК в часах, лучшие гости, средний чек — за день, неделю, месяц, квартал.
- **Сотрудники и роли.** Владелец входит ключом, сотрудники — своим логином и паролем (вход на 12 часов). Кассир: зал, смена, бар, гости, брони, сеансы. Только владелец: тарифы, каталог игр, запреты, бонусы и промокоды, аналитика, журнал, сотрудники, настройки, добавление и удаление ПК. В «Журнале» видно, кто что сделал.
- **Настройки → Telegram.** Токен бота от @BotFather и ID чата администраторов; кнопка «Отправить проверку».

## Главный экран, каталог из админки, Alt+Tab, «Мои файлы»

- **Главный экран** (по образцу клубных шеллов: левая колонка значков, вкладки «Игры» / «Приложения», справа профиль, баланс, сеанс и «Недавно запускали»). Он открывается **сразу после входа**, время покупается в окне «Тарифы» поверх него («Купить время»), без отдельного экрана выбора. Игры запускаются только в сеансе (иначе предлагается купить время). Избранное (сердечко) и недавние запуски запоминаются для каждого гостя.
- **Каталог игр и приложений теперь на сервере** и правится в админ-панели («Игры и приложения»): название, тип, группа, до 3 путей запуска (можно `find:Program.exe` для автопоиска), аргументы (`{user}`, `{pc}`), возраст, «клубный аккаунт», «закрепить на панели задач», включено, порядок, **обложка** (JPG/PNG/WEBP до 2 МБ, хранится на сервере, раздаётся с `/covers/…`). Оболочка берёт каталог с сервера и раз в минуту проверяет, не менялся ли он; если сервер недоступен или не настроен — работает файл `ui/config/catalog.json`. По умолчанию добавлены игры и приложения: Браузер (Chrome/Edge/Firefox), Discord, Telegram, Steam, Epic, Battle.net.
- **Запреты** (админ-панель → «Запреты»): список процессов, которые закрываются сразу после запуска в сеансе (например, `cheatengine-x86_64.exe`), гость видит сообщение. Работает также для файлов, открытых из «Моих файлов».
- **Закреплённые программы** показываются значками на панели задач (с настоящими иконками из exe).
- **Свой Alt+Tab** (в сеансе): плашка со значками окон по центру экрана, Tab листает, отпускание Alt выбирает, Esc отменяет. На заставке системный Alt+Tab по-прежнему блокируется.
- **«Мои файлы»** — собственный проводник: быстрый доступ к Загрузкам, Документам, Рабочему столу, Изображениям, Видео, Музыке и флешкам; создать папку, переименовать, копировать, вырезать, вставить, удалить, открыть. Системные папки, AppData и чужие профили недоступны, символические ссылки не открываются (логика `ClubShell.Core/GuestFileSystem`, покрыта тестами). Открывать можно только картинки, видео, музыку и PDF: программы, скрипты, ярлыки, архивы и текстовые файлы — нет (иначе через скачанный exe или диалог «Открыть» Блокнота гость добрался бы до cmd.exe).
- **Тест скорости** сначала меряет до сервера клуба (`/api/pc/speedtest/down|up`), затем при неудаче — через Cloudflare; при ошибке показывает конкретную причину.
